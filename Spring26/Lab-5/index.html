Module 5 Lab: C Structs, Pointers, and Dynamic Memory

This lab covers the following topics in C:

  • Declaring and using a struct type without typedef.
  • Using pointers to inspect how a struct and its members are laid out in memory.
  • Using pointers to read and write individual primitive variables.
  • Allocating primitives and structs on the heap with malloc and releasing them with free.
  • Using pass by reference and pointer arithmetic to modify arrays.

Lab Description

You will work through four parts in order. First you will define a struct Student, create instances with automatic storage, and use pointers only to observe addresses and sizes. Next you will practice primitive pointers on simple variables. Then you will use malloc to place data on the heap. Finally you will implement an in-place sort that takes an array by address and uses pointer arithmetic in the implementation.

Submission Format

For this lab, you will submit a single document (Word or PDF) containing:

  • Complete source code for each program you write (copy-paste into the document, or attach the corresponding .c files).
  • Screenshots of successful compilation with gcc and of each program's output, labeled by part.
  • Your answers to all conceptual questions, labeled by question number (e.g., Q1.2).

All code must compile and run with gcc.

Part 1: Anatomy of a (struct) Student

In this part, you will write a program which defines a custom struct Student type, and analyze how the fields of the struct are stored in memory.

Requirements

  • Define a struct Student that holds a char array of length 32 for the student's name, an int for the student's ID, and a double for the student's GPA.
  • Declare at least one struct Student variable and initialize its members (e.g., a sample name, id, and gpa).
  • Print the following using printf with appropriate format specifiers:
    • The size in bytes of the entire struct Student variable (Hint: You can get this value using the built-in sizeof operator).
    • The size in bytes of each member of your variable struct, e.g. sizeof(s.id)
    • The address of your variable and each of its members (Hint: Use the & operator to get the address of a variable, and %p as the format specifier to print it out).

Part 1 Conceptual Questions

Q1.1: What were the addresses of each struct field? How does this order relate to the order of the fields in your declaration?
Q1.2: Compute the sum of sizeof each member (name array, int, double). Is sizeof(struct Student) equal to that sum? If not, what might explain the difference?
Q1.3: What do you think would happen to the addresses of the struct fields if you switched the order in the struct definition? Try it out and see what happens. Were there any differences between the outcome and your prediction?
Q1.4: What do you think would happen if you tried to initialize a student with a name that is longer than 32 characters? Try it out and see what happens. Were there any differences between the outcome and your prediction?

Part 2: Primitive Pointers

In this part, you will write a program which creates variables and accesses their values indirectly through their memory addresses. We call this "Indirection".

Requirements

  • Declare int a, b; and double x; and initialize them to a random value of your choosing.
  • Declare int *pa and int *pb, set them to the addresses of a and b respectively.
  • Declare double *px pointing at x.
  • Use only the pointers (with *) to change at least one int and the double, then print the final values using either the variables or the pointers.
  • Print the addresses of a, b, and x so you can see three distinct locations.

Part 2 Conceptual Questions

Q2.1: What is the relationship between a variable's name (e.g., a), its address (&a), and the value at a pointer (*pa when pa == &a)?
Q2.2: Where in memory do automatic (local) variables like a and b typically live during a function call?
Q2.3: What would happen if you tried to dereference pa without setting its value properly?

Part 3: Using malloc

In this part, you will write a program that uses malloc and free from <stdlib.h> to allocate memory on the heap.

Requirements

  • Allocate an int on the heap, assign a value through the returned pointer, print the value, then free it.
  • Allocate an struct Student on the heap. Use sizeof correctly in the malloc call (e.g., malloc(sizeof(struct Student)) or malloc(sizeof *p) once p is declared with the right type).
  • Fill in the student's fields (use ->), print the record, then free the struct.
  • Allocate an array of int of size 10 on the heap, and initialize all of the elements
  • Free all heap-allocated variables once you are done with them.

Part 3 Conceptual Questions

Q3.1: Why is it important to use sizeof(struct Student) (or sizeof *p) rather than guessing a byte count when calling malloc for a student?
Q3.2: What should your program do if malloc returns NULL? When could this happen?
Q3.3: Compare the address printed for a heap-allocated struct Student with the address of a local struct Student from Part 1 (run both in one program if you like). What observation can you make about where each object lives?

Part 4: Sorting with Pass-by-Address and Pointer Arithmetic

In this part, you will implement a function that sorts an array of int in ascending order in-place. This means that it will actually modify the order of values in an array rather than just creating a separate sorted copy.

Requirements

  • Implement void sort(int *arr, int n); where n is the number of elements. The array is passed by address: the caller passes the address of the first element.
  • From main, declare an int array with at least 8 unsorted values, print it, call sort, then print the array again to show it is now sorted.
  • Implement a helper void swap_ints(int *a, int *b); (or similar) that exchanges two elements using pointers, and use it for your sort if appropriate.
  • Document in a comment which lines use pointer arithmetic explicitly.

Part 4 Conceptual Questions

Q4.1: Why does the arr parameter need to be a pointer rather than just a normal variable? What difference does this make?
Q4.2: Try passing in the array directly as an argument without & (if you haven't already implemented it this way). Why does this also work. What is the value represented by arr?
Q4.3: Why would it be useful to sort in-place rather than creating a sorted copy?
