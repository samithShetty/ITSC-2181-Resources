Module 2 Lab: RISC-V Assembly Programming in RARS

This lab covers the following course topics and goals:

  • Practice reading documentation to understand software behavior
  • Understanding the structure and execution flow of RISC-V assembly programs.
  • Proficiency with arithmetic, logic, and loading/storing instructions.
  • Understanding how bit-manipulation is used to perform mathematical operations.
  • Understanding the practical constraints and capabilities of assembly instructions.

Lab Description

In this lab, you will write RISC-V assembly programs using RARS (RISC-V Assembler and Runtime Simulator). You will start by understanding an existing Hello World program, then write increasingly complex programs of your own.

Submission Format

For this lab, you will submit a single document (Word or .pdf) containing:

  • Screenshots of successfully executed assembly code for each Part/Program
  • Your answers to all conceptual questions, labeled by question number (e.g., "Q2.1.3")

Part 1: Introduction to RARS and Hello World

In this part, you will set up RARS, learn the basic structure of a full RISC-V assembly program, and run a basic Hello World program.

Setup and Tutorial

Follow these steps to get started:

  • Tutorial: Watch this video walkthrough on RARS and documentation.
  • Download RARS: Go to the RARS repository on GitHub and scroll down to the Download section of the README . Install the appropriate version for your operating system.
  • Read the Hello World Tutorial: Read through the RARS Hello World tutorial to get an idea of what a full RISC-V program looks like. Make sure to read the code comments to understand what each line is doing
  • Copy and Execute: Copy the final Hello World program into RARS and execute it. Verify that the output appears in the console.
  • Extra Research: Take a closer look at the documentation shown in the walkthrough video and read through the Fundamentals of RISC-V Assembly to learn more!

Part 2: Arithmetic and Logic Instructions

In this part, you will write programs using arithmetic and logic instructions to perform mathematical and bitwise operations.

Program 2.1: Arithmetic Operations

Write a program that computes: x = ((y - z) / 2) * 17, where:

  • x is stored in register t0 (the final result)
  • y is stored in register t1 with initial value 12
  • z is stored in register t2 with initial value 20

After computing the result, print the value of x to the console. (Hint: use ecall with a7 = 1 to print an integer.)

Important: You cannot use pseudo-instructions such as li or mul for your programs. Use the real instructions that we have discussed in class.

Program 2.1 Skeleton:

.text
    .globl main

main:
    # TODO: Initialize registers

    # TODO: Compute x

    # Print x
    addi a0, t0, 0    # Move x into a0 for printing
    addi a7, x0, 1    # System call for print integer
    ecall

    # Exit
    addi a7, x0, 10
    ecall

Part 2.1 Conceptual Questions:

Q2.1.1: What RISC-V instruction(s) did you use to divide by 2 and why? What would happen if you used the alternative instruction?

Q2.1.2: What RISC-V instruction(s) did you use to multiply by 17? Explain how the math works out.

Program 2.2: Logic Operations (Bitwise NOT)

Write a program that computes: z = ~y (bitwise NOT of y), where:

  • y is stored in register t1 with initial value 2181
  • z is stored in register t2 (the result)

After computing the result, print the value of z to the console.

Important: You cannot use pseudo-instructions such as li or NOT. You must implement NOT using one of the logical instructions: and, or, or xor.

Hint: Which logical instruction flips 0s to 1s and 1s to 0s? (Try drawing a truth table if needed.)

Program 2.2 Skeleton:

    .globl main

main:
    # TODO: Initialize y

    # TODO:Compute z

    # Print z

Part 2.2 Conceptual Questions:

Q2.2.1: What is the binary representation of y (2181)? What is the binary representation of ~y?

Q2.2.2: What would be the result of z & y? What about z | y? Explain why.

Q2.2.3: What is the decimal value printed by your program for z? Does it match what you'd expect based on the value of y? Explain it's value using Two's Complement as a reference.

Q2.2.4: Is there a way to perform the NOT operation using just a single logical instruction? (hint: Think about immediates) Explain your reasoning.

  • Declares variables x = 21, y = 81, and z (uninitialized) in memory
  • Loads x and y from memory into registers
  • Computes z = x + y
  • Stores the result back into the memory location for z

Q3.1.1: After your program completes, check the Data Segment in RARS. What value is now stored in the memory location for z? What instruction put it there?

Q3.1.2: Why is it necessary to use the la (load address) instruction before using lw (load word)? What information does la provide that lw needs?

Q3.1.3: What would happen if you updated the register holding z's value after storing to memory? Would this update the value in memory as well? Explain why or why not.

Part 4: Challenge - Character Indexing and Printing

This is a challenge problem that combines memory access, dynamic indexing, and character I/O.

Write a program that:

  • Declares a string (array of characters) of your name in memory (e.g., .asciz "Chris")
  • Declares a variable i = 2 in memory
  • Loads i from memory
  • Loads the character at index i (i.e. name[i]) from the memory
  • Prints that character to the console

Note: Unlike standard integers, which are full words (4 bytes), a character is only a single byte of data. You will need to use a different instruction to load in your data. Also, printing a character, uses a different ecall code. See the RARS ecall reference table to figure out which environment call to use.

No skeleton for the Challenge Problem! Use previous questions and examples from documentation as a reference
